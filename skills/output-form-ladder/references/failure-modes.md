# 四种失效模式

升级形式不是单调改善。以下四种情况，**升级会让理解成本上升**。

---

## 1. 升错了级（成本最高的错误）

### 案例

用户问：「重启服务需要先停容器吗？」

**做成视频**：3 分 20 秒的动画，讲清容器编排的心智模型。

**结果**：用户原本 3 秒就能看完的答案，现在要看 3 分钟。

**净损失**：理解成本从 3 秒变 180 秒，且信息密度从「一个判断」变成「一个模型」。

### 判据

**如果原内容在一屏内能读完，就不要升级。**

再具体一点，满足任一条就该停在文字级：
- 答案能在一句话里说完
- 需要的是「是 / 否」或一个具体数值
- 内容在 200 字以内
- 用户只是想知道一个点，不是要理解一个系统

### 为什么容易犯

推荐形式的动作在心理上等价于「我给你做了更好的东西」。升级本身带来成就感，容易盖过成本核算。**所以要在动手前算，不要在做完后悔。**

---

## 2. HTML 用在了需要长期查阅的资料上

### 案例

把一份 20 页的 API 参考文档做成单文件 HTML。视觉上很精致。

### 四个具体损失

| 损失 | 后果 |
|---|---|
| 浏览器内 `Ctrl+F` 找不到全部内容 | 查一个参数要来回滚动 |
| 不能打印 | 无法带进会议 |
| 不能被搜索引擎索引 | 团队其他人找不到 |
| 对话里无法直接引用 | 沟通时要截图发 |

### 判据

问一句：**这份内容会被反复查阅吗？会被别人引用吗？会在团队里传吗？**

任一为「是」→ 用 Markdown，不用 HTML。

HTML 只适合「一次看完就结束」的展示型内容。

---

## 3. 视频用在了需要跳读的内容上

### 案例

把一份「部署步骤 + 故障排查」的教程做成 15 分钟视频。

### 为什么会崩

教程类内容的读者状态是**目标导向的**：他现在卡在第 3 步，只想看第 3 步。

视频强制线性播放。**读者要么从头看 15 分钟，要么拖进度条反复找——两个都是退步。**

### 判据

问一句：**读者会不会想「现在只查其中一段」？**

会 → 不做视频。做 Markdown + 折叠块（`<details>`），让结构承载导航。

### 视频真正适用的场景

- 物理直觉（为什么会有时间膨胀）
- 运动过程（三次握手的状态变化）
- 连续量变化（函数图像、波动率曲面）
- 空间关系（数据如何在网络中流动）
- 算法执行过程（快排的递归展开）

共同点：**这些都必须在「连续变化」中才能理解，拆成静态文字会丢掉过程本身。**

---

## 4. 把「80%」理解成「随便写」

### 案例

用户说「按 80% 的 ASD-STE100 标准写」，执行时把句长限制也去掉了。

### 为什么危险

80% 档放松的是**词表**，不是**结构**。

词表约束（只能用批准词）失效的后果：句子还是清楚的，只是用词不够标准 —— 轻微。

结构约束（动词开头、条件前置、句长上限）失效的后果：读者的工作记忆负担直接上升 —— **比完全不写 STE 更差**。

因为读者的预期被设定为「这已经被简化过了」，他会用更高的信任度去读，然后被超长的句子砸中。

### 操作定义

| 保留（放松即失效） | 可放松 |
|---|---|
| 动词开头 | 不查完整批准词表 |
| 条件在前 | 允许行业术语、必要被动句 |
| 句长上限 | 允许少量修饰语 |
| 不动代码标识符 | 允许一两个比喻 |
| 不发明数字 | — |

### 动作

用户说「80%」时，**先把这个解释讲清楚再动手**。不要等对方追问「那 50% 是什么」。

---

## 补充：第五种，没有症状的

### 形式对了，但内容错了

图很漂亮，网页很精致，视频很流畅——**但技术内容本身是错的**。

升形式会**放大**错误的传播速度：一段错误的文字读者会怀疑，一段错误的动画读者会直接记住。

**所以执行顺序永远是：先确认内容正确，再选形式。** 升级形式不能替代对内容的核对。
