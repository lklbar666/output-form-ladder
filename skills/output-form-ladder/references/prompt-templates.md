# 四级指令模板与验收清单

用法：直接复制模板，替换 `<>` 内容。**一次只用一级，不要一次生成四个版本让用户挑**——选择成本转嫁给用户等于没帮上忙。

---

## 第 1 级 · 受控文字（ASD-STE100）

### 80% 档的操作定义

保留结构约束，放松词汇约束。

| 保留（放松即失效） | 可放松 |
|---|---|
| 动词开头 | 不查完整批准词表 |
| 条件在前 | 允许行业术语、必要被动句 |
| 句长上限（英文指令 20 词 / 说明 25 词；中文 35 / 45 字） | 允许少量修饰语 |
| 不动代码、标识符、报错原文 | 允许一两个比喻 |
| 不发明数字 | — |
| 删掉不承载信息的词 | — |

### 指令模板

**标准档**
```
用 ASD-STE100 规范改写下面这段。先判断每句是指令型还是说明型，
指令型上限 20 词、说明型 25 词。一句一个动作。
保留代码块、标识符、报错原文不变。来源没给的数字不要补。
只输出改写结果，不输出改写理由。

<原文>
```

**80% 档**
```
用 ASD-STE100 的 80% 强度改写下面这段。
保留这四条：动词开头、条件前置、句长上限、不动代码标识符。
放松词表约束，允许保留必要的术语与被动句。
只输出改写结果。
```

**检查模式**（用户要的是检查不是改写）
```
检查下面这段是否符合 ASD-STE100。逐条列：
规则编号 + 原文片段 + 合规改写。不要凭记忆引规则编号。
最后说明：没有任何工具能保证合规，标准原文在 asd-ste100.org 免费下载。
```

### 验收

- 最长的三句是否在上限内
- 每个步骤是否点名了它依赖的**主机 / 参数位 / 前一步**
- 同一概念有没有用了两个同义词
- 报错原文有没有被缩写或「优化」

**边界**：如果「读不懂」来自词不认识而非句子装不下，去第二到第四级，改文字没用。

## 第 2 级 · 图表 / 结构图

### 指令模板

```
把这个内容画成一张图，不要写文字说明。

先判断图型并在输出里说明选了哪种：
- 有先后流程 → 流程图，箭头必须标方向
- 有包含层级 → 树状图
- 有状态切换 → 状态机，标注触发条件
- 有多组件依赖 → 架构图，标注数据流向
- 只有量级差异 → 条形图，必须标注单位与数值

产出：单文件 HTML，内联 SVG 或纯 CSS 布局。
不要引用任何外部资源（CDN、外链字体、外链图片），离线要能打开。

<内容>
```

### 验收

- **删掉图中任一元素，能否从剩下的推断出它？** 不能 → 该元素无用，删掉
- 每条连线是否有方向或含义？纯装饰连线删掉
- 数值是否标了单位？只写「高 / 低」的对比图无效
- 断网后能否打开（外部 CDN 会让图变空白块）

### 边界

图承载的是**关系**，不是装饰。如果图只是把文字排成方框、没有位置或连线的含义，它不如不画，改回文字。

## 第 3 级 · 可交互 HTML 网页

### 指令模板

```
把这个内容做成一个单文件 HTML 网页。

硬性要求：
- 单文件，CSS 与 JS 全部内联
- 不引用任何外部资源（CDN、外链字体、外链图片一律不用），离线可打开
- 响应式，手机与桌面都正常，不出现横向滚动条
- 中文正文不小于 17px
- 外部链接加 target="_blank" rel="noopener noreferrer"
- 时间用人类可读格式

内容要求：
- 首屏给结论，不要让读者先滚动才知道核心信息
- 有比较关系用表格，有层级关系用分区，有流程用有序列表
- 不要为了「看起来丰富」加动画

交互只允许这四类：筛选、排序、展开折叠、切换对比。
如果这四类用户一次都不会用，全部改成静态。

<内容>
```

### 验收

- 断网后双击能否打开
- 手机上会不会横向滚动
- 首屏是否给出了结论
- 交互是否真的解决了一个静态形式解决不了的问题

### 隐性成本（交付时必须说出口）

不能全屏阅读、不能打印、浏览器内 `Ctrl+F` 找不全内容、搜索引擎搜不到、对话里无法直接引用。

**需要反复查阅、需要被别人引用、需要在团队间传的内容，用 Markdown 不用 HTML。**

## 第 4 级 · 讲解视频

### 指令模板（用户提供了 API key）

```
做一个 3Blue1Brown 风格的讲解视频，讲讲 <主题>。
用我的 ElevenLabs API key 配旁白。

先产出（不要直接开始渲染）：
1. 逐句旁白稿，每句标注它对应画面的哪个元素
2. 分镜表：镜号、时间、画面内容、旁白、该镜头要让人理解什么
3. 渲染脚本与依赖清单

脚本要求：
- 关键概念先给直觉，再给形式化定义
- 旁白用短句，不复述画面已经写出来的字
- 画面讲解的概念不能只靠旁白带过

画面要求：
- 一个概念一个画面，不叠加
- 动画服务于理解，不是炫技
- 每个关键帧停留不少于 2 秒
```

### 指令模板（用户没有 API key）

```
做一个 3Blue1Brown 风格的讲解视频，讲讲 <主题>。

先不要生成。产出：
1. 逐句旁白稿
2. 分镜表
3. 列出需要我提供什么，以及有哪些可在本机免费运行的替代方案
```

### 免费替代方案

| 环节 | 方案 | 特点 |
|---|---|---|
| 中文 TTS | `edge-tts` | 微软 Edge 朗读接口，中文自然度较好，需联网 |
| 中文 TTS | `Piper` | 完全离线，音质中等 |
| 中文 TTS | 系统 SAPI 语音 | Windows 自带，零安装，机械感明显 |
| 视频合成 | `ffmpeg` + Pillow | 零学习成本，只能做静态图 + 平移缩放 |
| 视频合成 | `remotion` | 用 React 写动画，适合数学可视化 |
| 最省事 | 只出旁白稿 + 分镜表 | 用现成录屏工具录，交付成本最低 |

### API key 处理规则（硬性）

1. **不要**把 API key 写进任何生成的文件、命令行参数、配置文件或对话回复
2. 只在运行时从环境变量或用户当场提供的凭据通道读取
3. 用户把 key 直接贴在对话里时，**明确提醒：这个 key 已暴露在会话记录中，建议用完轮换**
4. 在产物 README 里写明需要哪些环境变量名，但**不写值**

### 验收

- 旁白稿里有没有复述画面已有的文字
- 有没有概念只靠旁白带过、没在画面上呈现
- 关键帧停留是否足够读完
- 用户能不能只看分镜表就讲完（分镜不合格 = 视频不合格）

### 边界

视频不承载精确数值、不支持跳读、不支持复制命令、不被搜索引擎索引。**教程类、操作类、需要「现在只查第 3 步」的内容上，视频是纯粹的退步。**
