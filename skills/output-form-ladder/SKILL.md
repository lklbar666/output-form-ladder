# 输出形式升级阶梯

## 核心判断

**「再解释一遍」几乎总是错的。** 它的默认假设是「问题出在文字表达上」。实际多数情况是**问题的信息密度超出了纯文字的承载上限**——文字必须线性阅读，读者要自己在脑子里重建拓扑关系、连续量变化和因果链。再换一套词解释，只会让同样的信息换一种排列方式塞回去。

正确的动作是**换媒介**，不是换措辞。

阶梯按「理解成本」递减排列。四级不是质量高低，是**适用内容不同**。

---

## 何时用 / 何时不用

| 用 | 不用 |
|---|---|
| 读者说「看不懂」「太绕」「说人话」 | 读者要的是精确数值或可复制的命令 |
| 概念需要建立直觉（拓扑、流程、运动、比例） | 问题答案是「是」或「否」 |
| 一次要讲透多个相互关联的部分 | 读者要在 3 秒内拿到结论 |
| 反复讲解同一主题（培训、答疑、科普） | 内容需要被搜索、跳读、引用 |
| 要给别人展示，读者不是专业人士 | 读者环境不保证能开网页或看视频 |

**同时用 ste-plain-writer**：如果「读不懂」来自文字本身写得差（词都认识、句子读得通，但没有信息），**先改文字，换形式没用**。本技能管的是媒介选择，不是写作质量。

## 阶梯

### 第一级 · 受控文字

**工具**：ASD-STE100 简明技术英语
**本地技能**：`ste-plain-writer`

**「80% 档」的操作定义**：Karpathy 说这套规范「太严了，有时候我会让它松一点，比如说『按 80% 的 ASD-STE100 标准来写』」。

80% 档 = **保留结构约束，放松词汇约束**。

| 80% 档保留（不可放松） | 80% 档可放松 |
|---|---|
| 动词开头 | 不用查完整批准词表 |
| 条件在前 | 允许行业术语、允许必要的被动句 |
| 句长上限（英文 20/25 词，中文 35/45 字） | 允许保留少量修饰语 |
| 不动代码/标识符/报错原文 | 允许一两个比喻 |
| 不发明数字 | — |
| 删掉不承载信息的词 | — |

**用户说「80%」不等于「可以随便写」**。结构约束放松了会立刻失效，这是最常见的误读。

**指令模板**：
```
用 ASD-STE100 的 80% 强度改写下面这段。保留动词开头、条件前置、句长上限、
不动代码标识符这四条。放松词表约束，允许保留必要的术语与被动句。
不要输出改写理由，只输出改写结果。
```

**验收**：最长的三句是否在上限内？每个步骤是否点名了它依赖的主机/参数/前一步？

---

### 第二级 · 图表 / 结构图

**适用**：流程、架构、层级、状态机、依赖关系、时间线、量级对比。

**核心原则**：**图承载的是「关系」，不是「装饰」。** 如果图只是把文字排成方框，没有任何位置或连线的含义，它不如不画。

**指令模板**：
```
把这个内容画成一张图，不要写文字说明。

先判断图型：
- 有先后流程 → 流程图（带方向标注）
- 有包含层级 → 树状图
- 有状态切换 → 状态机（标注触发条件）
- 有多组件依赖 → 架构图（标注数据流向）
- 只有量级差异 → 条形图（必须标注单位与数值）

[可选] 画完后在图下方用不超过 3 句说明这张图回答了什么问题。
```

**验收**：
- 删掉图中任一元素，能否从剩下的元素推断出它？不能说明该元素无用 → 删。
- 每个连线是否有方向或含义？纯装饰的连线删掉。
- 数值必须标注单位。只写「高/低」的对比图无效。

**产出形态**：单文件 HTML（内联 SVG 或纯 CSS 布局）。不用外部库——外部 CDN 会让图在离线或内网环境变成空白块。

---

### 第三级 · 可交互 HTML 网页

**适用**：需要探索、筛选、排序、切换视角的内容；需要同时呈现多个维度；需要长期查阅且读者会来回跳。

**核心原则**：**交互必须解决一个具体的、静态形式解决不了的问题。** 筛选、排序、展开折叠、切换对比——如果这些操作用户一次也不会做，交互是纯成本。

**指令模板**：
```
把这个内容做成一个单文件 HTML 网页。

硬性要求：
- 单文件，CSS 与 JS 全部内联，不引用任何外部资源（CDN、外链字体、外链图片一律不用）
- 离线可打开
- 响应式，手机与桌面都正常
- 中文正文不小于 17px
- 外部链接加 target="_blank" rel="noopener noreferrer"

内容要求：
- 首屏给结论，不要让读者先滚动才能知道核心信息
- 有比较关系用表格，有层级关系用分区，有流程用有序列表
- 不要为了「看起来丰富」加动画

[可选] 需要交互的只有以下几类：筛选、排序、展开折叠、切换对比。其余一律静态。
```

**验收**：断网后双击能否打开？手机上会不会横向滚动条？首屏是否给出了结论？

**隐性成本（必须提前告知用户）**：不能全屏阅读、不能打印、浏览器内搜索困难、不适合被搜索引擎索引。**需要反复查阅或需要被引用的资料，用 Markdown 不用 HTML。**

---

### 第四级 · 讲解视频

**适用**：物理直觉、运动过程、连续量的变化、空间关系、算法执行过程、需要长期记忆的复杂概念。

**不适用**：精确数值、需要复制的内容、需要跳读的教程、需要检索的内容。

**Karpathy 的原话**：「我最看好的输出形式是这个：任何话题都能让 AI 给你量身定做一个讲解视频。可以试试这样说：『做一个 3Blue1Brown 风格的视频，讲讲 XX。用我的 ElevenLabs API key 配旁白。』」

**指令模板**：
```
做一个 3Blue1Brown 风格的讲解视频，讲讲 <主题>。

旁白：[用户提供 ElevenLabs API key 时] 用我的 ElevenLabs API key 配旁白。
      [未提供时] 先不要生成。列出需要我提供什么，以及有哪些可在本机免费运行的替代方案。

脚本要求：
- 先写逐句旁白稿，每句标注它对应画面的哪个元素
- 旁白用短句，不要复述画面已经写出来的字
- 关键概念先给直觉，再给形式化定义

画面要求：
- 一个概念一个画面，不叠加
- 动画服务于理解，不是炫技
- 每个关键帧停留不少于 2 秒
```

**API key 处理规则（硬性）**：
- **不要**把 API key 写进任何生成的文件、命令行参数、配置文件或对话回复里
- 只在运行时从环境变量或用户当场提供的凭据通道读取
- 用户把 key 贴在对话里时，提醒他这个 key 已经暴露在会话记录中，**建议用完轮换**

**免费替代方案**（用户没有 ElevenLabs 时提供选项，不要硬凑）：
- 本机 TTS：`edge-tts`（微软 Edge 朗读接口，中文自然度较好）、`Piper`（完全离线）、系统 `SAPI` 语音
- 视频合成：`ffmpeg` + `Pillow`/`remotion`
- **最省事**：只出旁白稿 + 分镜表，用现成工具录

## 选型决策表

按**内容性质**选，不按话题酷不酷选。

| 内容性质 | 用哪级 | 为什么 |
|---|---|---|
| 有精确数值、需查证、可复制 | 文字 / 表格 | 图和视频不承载精确值，读者无法复制 |
| 流程、架构、状态机、依赖关系 | 图 → HTML | 文字要求读者重建拓扑 |
| 需要筛选、排序、多维对比 | HTML | 静态图无法响应 |
| 物理直觉、运动、连续变化、空间关系 | 视频 | 文字无法承载连续量的直觉 |
| 一次讲透多个关联部分 | 图 + HTML | 单张图装不下，文字又太长 |
| 反复讲解同一主题（培训/科普） | 视频 | 重复讲解的边际成本最低 |
| 结论先行、快速决策 | **文字** | **升级形式会净增加理解成本** |
| 需要被搜索、跳读、引用 | **Markdown** | HTML 与视频都不可检索 |

**默认起点是文字。** 升级的唯一理由是「读不懂」，不是「想要更好看」。

## 执行流程

1. **判定是不是形式问题。** 问一句：读者是「不认识这些词」，还是「认识但装不下」？前者去 `ste-plain-writer`，后者继续。
2. **查决策表定级。** 内容性质决定级别，不靠感觉。
3. **生成。** 用该级的指令模板。一次只做一级，不要一次生成四个版本让用户挑——**选择成本由用户承担，等于没帮上忙**。
4. **按该级的验收标准自查。** 不合格就修，不要交出去让用户发现。
5. **告知隐性成本。** 每一级都有代价（见各节），必须说，不要默默交付。
6. **仍读不懂才升一级。** 一次只升一级。连升两级说明第一步没做对。

## 失效模式：升级反而更糟的四种情况

### 1. 升错了级 —— 成本最高的错误

把「重启服务需要先停容器」这个 15 字能说清的问题做成 3 分钟视频，理解成本从 3 秒变成 3 分钟。**净损失。**

**判据**：如果原内容在一屏内能读完，就不要升级。

### 2. HTML 用在了需要长期查阅的资料上

HTML 好看，但：不能全屏、不能打印、浏览器内 `Ctrl+F` 找不全、搜索引擎搜不到、不能在对话里直接引用。

**需要被反复查阅、需要被别人引用、需要在团队间传的内容，用 Markdown。** HTML 只适合「一次看完就结束」的展示型内容。

### 3. 视频用在了需要跳读的内容上

教程类、操作类内容，读者需要「现在只查第 3 步」。视频强制线性播放。**这类内容上视频是纯粹的退步。**

### 4. 把「80%」理解成「随便写」

80% 档放松的是词表，不是结构。放松结构约束（不限制句长、不做动词开头）后，读者的认知负担会上升，**比不写 STE 更差**。

**在动手前把这个解释讲清楚，不要等到用户追问。**
